# let/const 与 var 的区别（块级作用域、暂时性死区、不挂载到 window）

ES6（ES2015）引入了 `let` 和 `const` 两个新的声明关键字，从根本上弥补了 `var` 的设计缺陷。下面从四个维度逐一拆解。

---

## 一、作用域：函数作用域 vs 块级作用域

### var —— 函数作用域

`var` 的作用域是**整个函数体**，不受 `{}` 代码块限制。

```javascript
function demo() {
  if (true) {
    var a = 1;
  }
  console.log(a); // 1 —— if 块外依然能访问
}
demo();
```

经典的循环变量泄漏问题：

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出：3 3 3（而非 0 1 2）
// 因为 i 是同一个函数级变量，循环结束时 i 已为 3
```

### let / const —— 块级作用域

`let` 和 `const` 的作用域是**最近的一对** `{}`，包括 `if`、`for`、`while`、`switch` 以及独立的代码块。

```javascript
function demo() {
  if (true) {
    let a = 1;
    const b = 2;
  }
  console.log(a); // ReferenceError: a is not defined
  console.log(b); // ReferenceError: b is not defined
}
```

循环中每次迭代都是独立的作用域绑定：

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出：0 1 2 —— 每次循环的 i 是独立的块级绑定
```

> **注意**：`for (let i...)` 中，`i` 的作用域是整个循环体，且每次迭代会创建一个新的绑定。这是 `let` 在 `for` 循环中的特殊行为。

## 二、变量提升与暂时性死区（TDZ）



### var —— 声明提升，初始化为 undefined

`var` 声明会被提升到函数顶部，并初始化为 `undefined`，所以在声明前访问不会报错。

```javascript
console.log(a); // undefined（不报错）
var a = 1;
```

等价于：

```javascript
var a = undefined; // 提升并初始化
console.log(a);    // undefined
a = 1;
```



### let / const —— 声明提升，但不初始化（暂时性死区）

`let` 和 `const` 同样会被提升（hoisting），但**在声明语句执行之前，变量处于"暂时性死区"（Temporal Dead Zone, TDZ）**，访问会直接抛出 `ReferenceError`。

```javascript
console.log(a); // ReferenceError: Cannot access 'a' before initialization
let a = 1;
```

```javascript
console.log(b); // ReferenceError: Cannot access 'b' before initialization
const b = 2;
```

TDZ 的起止范围：

```javascript
function demo() {
  // —— TDZ 开始 ——
  console.log(x); // ❌ ReferenceError
  // —— TDZ 结束（声明语句执行完毕）——
  let x = 10;
  console.log(x); // ✅ 10
}
```

一个容易踩坑的 TDZ 场景：

```javascript
let x = 1;
{
  console.log(x); // ❌ ReferenceError
  // 因为块内也声明了 let x，整个块的开头到声明语句之间都是 TDZ
  let x = 2;
}
```

## 三、全局对象挂载：var 挂到 window，let/const 不挂

在全局作用域中：

- `var` 声明的变量会成为**全局对象** `window`**（浏览器）/** `global`**（Node）的属性**
- `let` 和 `const` 声明的变量**不会**挂载到全局对象，它们存在于独立的"全局词法环境"中

```javascript
var a = 1;
let b = 2;
const c = 3;

console.log(window.a); // 1（浏览器环境）
console.log(window.b); // undefined
console.log(window.c); // undefined
```

这意味着 `let/const` 不会意外覆盖全局对象上的已有属性：

```javascript
var window.innerWidth = 0;   // 可能覆盖浏览器原生属性（危险）
let innerWidth = 0;          // 安全，不影响 window.innerWidth
```

## 四、重复声明与重新赋值



### var —— 可重复声明

```javascript
var a = 1;
var a = 2; // 合法，后面的覆盖前面的
console.log(a); // 2
```



### let —— 同一作用域不可重复声明

```javascript
let a = 1;
let a = 2; // SyntaxError: Identifier 'a' has already been declared
```

但可以重新赋值：

```javascript
let a = 1;
a = 2; // ✅ 合法
```



### const —— 不可重复声明 + 不可重新赋值 + 必须初始化

```javascript
const a;     // SyntaxError: Missing initializer in const declaration
const a = 1;
a = 2;       // TypeError: Assignment to constant variable
```

**重要：const 保证的是"引用不可变"，而非"值不可变"。** 对于对象和数组，内部属性仍然可以修改：

```javascript
const obj = { name: 'Alice' };
obj.name = 'Bob';   // ✅ 合法（修改的是属性，不是引用）
obj.age = 20;       // ✅ 合法

obj = { name: 'Tom' }; // ❌ TypeError（重新赋值引用）

const arr = [1, 2, 3];
arr.push(4);       // ✅ 合法
arr[0] = 10;       // ✅ 合法
```

如果需要对象完全不可变，使用 `Object.freeze()`：

```javascript
const obj = Object.freeze({ name: 'Alice' });
obj.name = 'Bob'; // 严格模式下报错，非严格模式静默失败
```

## 面试总结

let,const和var的主要区别在三个方面:

1. 作用域不同:let,const采用块级作用域，匹配最近的一对`{}`; Var是函数级作用域，作用域在整个函数体，不受{}代码块限制。
2. 变量提升与暂时性死区(TDZ): var声明变量会被提升到函数顶部，并初始化为undefined，所以在声明前访问不会报错。 let,const也会被提升，但在执行之前处于暂时性死区，访问会抛出错误。
3. 全局对象挂载：在全局作用域中: var声明的变量会成为全局对象`window`(浏览器)/`global(Node)`的属性，let,const声明的变量不会挂载到全局对象,独立存在于全局环境中。
