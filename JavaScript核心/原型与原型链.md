# 原型与原型链

# JavaScript 原型与原型链详解

## 一、`__proto__`、`prototype`、`constructor` 三者关系

### 1. 基本概念


| 属性            | 所属                                | 含义                        |
| ------------- | --------------------------------- | ------------------------- |
| `prototype`   | **函数（构造函数）** 的属性                  | 一个对象，包含该构造函数所有实例共享的属性和方法  |
| `__proto__`   | **每个对象** 都有的内部属性（`[[Prototype]]`） | 指向创建该对象的构造函数的 `prototype` |
| `constructor` | **原型对象** 的属性                      | 指回该原型对象所属的构造函数            |


### 2. 核心关系图

```
function Person() {}

const p = new Person();

p.__proto__ === Person.prototype;           // true
Person.prototype.constructor === Person;    // true
p.constructor === Person;                   // true（继承自原型）
```

用一张图表示：

prototype

### 3. 关键点

- **只有函数才有** `prototype`，普通对象没有（但有 `__proto__`）。
- `__proto__` 是访问器属性（getter/setter），实际指向内部的 `[[Prototype]]`，推荐用 `Object.getPrototypeOf()` / `Object.setPrototypeOf()` 替代。
- 实例本身没有 `constructor`，是沿着原型链找到 `Person.prototype.constructor`。

## 二、原型链查找机制



### 1. 查找过程

当访问对象的某个属性时，JavaScript 引擎的行为：

1. **先在对象自身**查找，找到则返回；
2. 没找到，去 `obj.__proto__`（即构造函数的 prototype）上找；
3. 还没找到，继续往上 `obj.__proto__.__proto__` 找；
4. 直到 `Object.prototype`；
5. `Object.prototype.__proto__ === null`，查找终止，返回 `undefined`。

这条由 `__proto__` 串联起来的链就是**原型链**。

```js
const obj = {};
obj.toString();
// 查找路径：obj → obj.__proto__(Object.prototype) → 找到 toString → 调用
// Object.prototype.__proto__ → null（终止）
```



### 2. `Object.prototype.__proto__ === null`

这是原型链的**终点**，设计上的刻意为之：

```js
Object.prototype.__proto__ === null;  // true
```

含义：`Object.prototype` 是所有对象的"根原型"，它不再继承任何东西，所以其 `[[Prototype]]` 为 `null`。这保证了原型链不会无限循环。

### 3. 属性遮蔽（Shadowing）

如果对象自身和原型链上有同名属性，**优先返回自身的**：

```js
function Person() {}
Person.prototype.name = '原型';

const p = new Person();
p.name = '实例';
console.log(p.name);  // '实例'（自身遮蔽了原型）
```

判断属性来源：

- `obj.hasOwnProperty(prop)` —— 是否是自身属性
- `prop in obj` —— 自身或原型链上是否存在

## 三、继承的 6 种方式



### 1. 原型链继承

**核心思想**：子类的原型指向父类的实例。

```js
function Parent() {
  this.name = 'parent';
  this.colors = ['red', 'blue'];
}
Parent.prototype.say = function () {
  console.log(this.name);
};

function Child() {}
Child.prototype = new Parent();  // 关键：子类原型 = 父类实例

const c1 = new Child();
const c2 = new Child();
c1.colors.push('green');
console.log(c2.colors);  // ['red', 'blue', 'green'] —— 被污染了！
```

**优点**：

- 简单易实现，父类方法可复用

**缺点**：

- 所有子类实例**共享父类引用类型属性**，一个修改全部受影响
- 创建子类实例时无法向父类构造函数传参
- 无法实现多继承

---



### 2. 构造函数继承（经典继承 / 借用构造函数）

**核心思想**：在子类构造函数中调用父类构造函数，用 `call/apply` 绑定 `this`。

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

function Child(name, age) {
  Parent.call(this, name);  // 借用父类构造函数
  this.age = age;
}

const c1 = new Child('Tom', 18);
const c2 = new Child('Jerry', 20);
c1.colors.push('green');
console.log(c2.colors);  // ['red', 'blue'] —— 互不影响
```

**优点**：

- 解决了引用类型共享问题
- 子类实例可以向父类构造函数传参
- 可以实现多继承（call 多个父类）

**缺点**：

- 方法都在构造函数中定义，**无法复用**，每个实例都有一份方法副本
- 父类原型上的方法子类不可见（因为没有原型链关系）

---



### 3. 组合继承（伪经典继承）

**核心思想**：原型链继承 + 构造函数继承，两者结合。

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}
Parent.prototype.sayName = function () {
  console.log(this.name);
};

function Child(name, age) {
  Parent.call(this, name);   // 第二次调用 Parent
  this.age = age;
}
Child.prototype = new Parent();  // 第一次调用 Parent
Child.prototype.constructor = Child;  // 修正 constructor 指向

const c = new Child('Tom', 18);
c.sayName();  // 'Tom'
```

**优点**：

- 兼具原型链继承（方法复用）和构造函数继承（实例属性独立、可传参）的优点
- 是 JavaScript 中最常用的继承模式

**缺点**：

- **父类构造函数被调用了两次**：一次在创建子类原型时，一次在子类构造函数内部
- 导致子类原型上存在一份多余的父类实例属性（被实例属性遮蔽，浪费内存）

---



### 4. 原型式继承

**核心思想**：借助原型，基于已有对象创建新对象，不必创建自定义类型。

```js
// ES5 之前的手动实现
function object(o) {
  function F() {}
  F.prototype = o;
  return new F();
}

// ES5 之后用 Object.create 规范化
const parent = {
  name: 'parent',
  colors: ['red', 'blue'],
};

const child = Object.create(parent);
child.name = 'child';
child.colors.push('green');

const another = Object.create(parent);
console.log(another.colors);  // ['red', 'blue', 'green'] —— 共享引用类型
```

**优点**：

- 无需创建构造函数，适合只想让一个对象与另一个对象保持类似的场景
- `Object.create` 支持第二个参数定义额外属性

**缺点**：

- 引用类型属性仍然会被所有实例共享（和原型链继承一样的问题）
- 无法做到函数复用（没有构造函数）

---



### 5. 寄生式继承

**核心思想**：在原型式继承的基础上，用一个函数"封装"创建过程，并在内部增强对象。

```js
function createAnother(original) {
  const clone = Object.create(original);  // 原型式继承
  clone.sayHi = function () {             // 增强对象
    console.log('hi');
  };
  return clone;
}

const parent = { name: 'parent' };
const child = createAnother(parent);
child.sayHi();  // 'hi'
```

**优点**：

- 在不自定义类型的情况下，给对象添加方法
- 思路简单，适合只关注对象、不关注构造函数的场景

**缺点**：

- 方法在函数内部定义，**无法复用**，每个对象都有一份方法副本
- 引用类型属性共享问题依然存在

---



### 6. 寄生组合式继承（最优方案）

**核心思想**：用构造函数继承属性，用原型链的混成形式继承方法，**避免调用两次父类构造函数**。

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}
Parent.prototype.sayName = function () {
  console.log(this.name);
};

function Child(name, age) {
  Parent.call(this, name);   // 继承属性（只调用一次父类构造函数）
  this.age = age;
}

// 关键：不直接 new Parent()，而是让子类原型继承父类原型
function inheritPrototype(Child, Parent) {
  const prototype = Object.create(Parent.prototype);  // 创建对象
  prototype.constructor = Child;                      // 修正 constructor
  Child.prototype = prototype;                        // 指定对象
}

inheritPrototype(Child, Parent);

const c = new Child('Tom', 18);
c.sayName();  // 'Tom'
```

**优点**：

- 父类构造函数**只调用一次**，效率更高
- 子类原型上没有多余的父类实例属性
- 原型链保持正常，可正常使用 `instanceof` 和 `isPrototypeOf`
- 被公认为**引用类型最理想的继承范式**

**缺点**：

- 实现相对复杂，需要理解寄生 + 组合的思路
- 代码量稍多（可封装工具函数解决）

---



## 四、6 种继承方式对比总结


| 继承方式   | 核心实现                                     | 引用属性共享 | 方法复用 | 可传参 | 调用父类次数 |
| ------ | ---------------------------------------- | ------ | ---- | --- | ------ |
| 原型链继承  | `Child.prototype = new Parent()`         | ✗ 共享   | ✓    | ✗   | 1      |
| 构造函数继承 | `Parent.call(this)`                      | ✓ 独立   | ✗    | ✓   | 1      |
| 组合继承   | 原型链 + 构造函数                               | ✓ 独立   | ✓    | ✓   | 2      |
| 原型式继承  | `Object.create(o)`                       | ✗ 共享   | ✗    | ✗   | 0      |
| 寄生式继承  | 原型式 + 内部增强                               | ✗ 共享   | ✗    | ✗   | 0      |
| 寄生组合式  | `Object.create(Parent.prototype)` + call | ✓ 独立   | ✓    | ✓   | 1      |

## 五、补充：ES6 `class` 语法

ES6 的 `class` 本质是寄生组合式继承的**语法糖**：

```js
class Parent {
  constructor(name) {
    this.name = name;
  }
  sayName() {
    console.log(this.name);
  }
}

class Child extends Parent {
  constructor(name, age) {
    super(name);  // 相当于 Parent.call(this, name)
    this.age = age;
  }
}
```

`extends` 底层做的事情和寄生组合式继承一致，所以理解了上面 6 种方式，也就理解了 `class` 的本质。

## 面试总结

每个构造函数的身上都`prototype`属性，它是一个对象,包含该构造函数所有实例共享的属性和方法。`__proto__`是每个对象都有的内部属性，它指向创建该对象的构造函数的`prototype` 。`constructor` 是原型对象(prototype)的属性，指向该原型对象所属的构造函数。

原型链的查找机制为：

当访问对象的某个属性时，JavaScript引擎的行为：

1. 先在对象自身查找，找到则返回;
2. 没找到，去 `obj.__proto__`（即构造函数的 prototype）上找；
3. 还没找到，继续往上 `obj.__proto__.__proto__` 找；
4. 直到 `Object.prototype`；
5. `Object.prototype.__proto__ === null`，查找终止，返回 `undefined`。

继承的6种方式为:原型链继承，构造函数继承，组合继承，原型式继承，寄生式继承，寄生组合式继承。其中寄生组合式是继承的最好实现。
