# 作用域与闭包

# JavaScript 作用域与闭包详解

## 一、词法作用域 vs 动态作用域

### 1.1 词法作用域（Lexical Scope）

JavaScript 采用的是**词法作用域**（也叫静态作用域）。变量的查找范围在代码**书写时**就已确定，与函数在哪里调用无关，只与函数在哪里**定义**有关。

```javascript
var a = 1;

function foo() {
  console.log(a); // 查找 a：先看 foo 内部，没有 → 看外层全局，找到 a=1
}

function bar() {
  var a = 2;
  foo(); // 输出 1，而不是 2
}

bar();
```

即使 `foo` 在 `bar` 内部被调用，它仍然去自己**定义时**的外层作用域（全局）找 `a`，这就是词法作用域的核心特征。

### 1.2 动态作用域（Dynamic Scope）

动态作用域下，变量查找取决于函数**调用时**的上下文，而非定义位置。Bash、Perl 等语言支持动态作用域。

如果上面的代码是动态作用域，`foo` 会输出 `2`（从调用者 `bar` 的作用域中查找）。

### 1.3 关键区别


| 维度   | 词法作用域                  | 动态作用域         |
| ---- | ---------------------- | ------------- |
| 确定时机 | 代码书写（编译/解析阶段）          | 运行时调用阶段       |
| 查找依据 | 函数定义位置                 | 函数调用栈         |
| 代表语言 | JavaScript、Python、Java | Bash、Perl（部分） |


> JavaScript 的 `this` 绑定机制有点像动态作用域，但 `this` 不是作用域查找，而是函数调用方式决定的对象绑定，不要混淆。

## 二、执行上下文、变量对象/活动对象、作用域链



### 2.1 执行上下文（Execution Context）

执行上下文是 JavaScript 代码执行的环境，每段代码运行都在某个执行上下文中。

**三种类型：**

- **全局执行上下文**：程序启动时创建，唯一，`this` 指向全局对象（浏览器中为 `window`）。
- **函数执行上下文**：函数被调用时创建，每次调用都是一个新的上下文。
- **Eval 执行上下文**：`eval()` 内部代码的上下文（不推荐使用）。

**生命周期：**

```
创建阶段（Creation Phase）  →  执行阶段（Execution Phase）
  - 创建变量对象(VO)            - 逐行执行代码
  - 建立作用域链                - 变量赋值
  - 确定 this 指向              - 函数引用
```



### 2.2 变量对象（VO）与活动对象（AO）

**变量对象（Variable Object, VO）**：执行上下文创建阶段生成的对象，存储当前上下文中的变量、函数声明和形参。

- 全局上下文的 VO 就是全局对象本身。
- 函数上下文的 VO 在创建阶段存在，进入执行阶段后变为**活动对象（Activation Object, AO）**。

**VO/AO 的创建过程（变量提升的本质）：**

```javascript
function test(a) {
  console.log(a);      // ƒ a() {}  — 函数声明优先级高于参数
  console.log(b);      // undefined — 变量声明提升，赋值未提升
  var a = 1;
  var b = function() { return 2; };
  function a() {}
}
test(10);
```

创建阶段 VO 的填充顺序：

1. 函数的形参（`a: 10`）
2. 函数声明（`a: function`，**覆盖**同名参数）
3. 变量声明（`b: undefined`，不覆盖已有的函数声明）

所以 `a` 最终是函数，`b` 是 `undefined`。

> **优先级**：函数声明 > 形参 > 变量声明（同名时后者不覆盖前者）。



### 2.3 作用域链（Scope Chain）

作用域链是当前执行上下文的 VO/AO 与所有外层执行上下文 VO 组成的链式结构，用于变量查找。

```javascript
var x = 10;

function outer() {
  var y = 20;
  
  function inner() {
    var z = 30;
    console.log(x + y + z); // 60
  }
  
  inner();
}

outer();
```

`inner` 执行时的作用域链：

```
inner 的 AO (z=30) → outer 的 AO (y=20) → 全局 VO (x=10) → null
```

**查找规则**：从链的前端（当前 AO）开始逐级向后查找，找到即停止；找不到则报 `ReferenceError`。

作用域链的前端始终是当前执行上下文的活动对象，末端是全局执行上下文的变量对象。

## 三、闭包（Closure）



### 3.1 定义

**闭包是指有权访问另一个函数作用域中变量的函数。**

更准确地说：当一个内部函数引用了外部函数的变量，并且内部函数在外部函数之外被调用时，内部函数连同它所引用的外部变量环境，共同构成了闭包。

```javascript
function outer() {
  var count = 0;
  
  return function inner() {
    count++;
    return count;
  };
}

var counter = outer();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

`outer` 执行完毕后，其执行上下文已出栈，但 `count` 变量没有被销毁——因为 `inner` 函数通过闭包持有了对它的引用。

### 3.2 产生条件

闭包产生必须同时满足三个条件：

1. **函数嵌套**：存在内层函数和外层函数的嵌套关系。
2. **引用自由变量**：内层函数引用了外层函数的局部变量（自由变量）。
3. **外部调用**：内层函数在其外层函数之外被调用（通常通过 return、赋值给外部变量、作为回调等方式）。

```javascript
// 不构成闭包：inner 没有在 outer 外部被调用
function outer() {
  var a = 1;
  function inner() { console.log(a); }
  inner(); // 普通的作用域链查找，不形成闭包
}

// 构成闭包：inner 被返回并在外部调用
function outer() {
  var a = 1;
  return function inner() { console.log(a); };
}
var fn = outer();
fn(); // 闭包
```



### 3.3 常见应用场景



#### 场景一：防抖（Debounce）

在事件被触发 n 秒后再执行回调，如果 n 秒内又被触发，则重新计时。

```javascript
function debounce(fn, delay) {
  var timer = null;  // 闭包变量：保存定时器 ID
  
  return function() {
    var context = this;
    var args = arguments;
    
    clearTimeout(timer);
    timer = setTimeout(function() {
      fn.apply(context, args);
    }, delay);
  };
}

// 使用
var handleSearch = debounce(function(value) {
  console.log('搜索:', value);
}, 300);

input.addEventListener('input', function(e) {
  handleSearch(e.target.value);
});
```



#### 场景二：节流（Throttle）

规定在一个单位时间内，只能触发一次函数。如果这个单位时间内触发多次，只有一次生效。

```javascript
// 时间戳版
function throttle(fn, interval) {
  var lastTime = 0;  // 闭包变量：记录上次执行时间
  
  return function() {
    var now = Date.now();
    var context = this;
    var args = arguments;
    
    if (now - lastTime >= interval) {
      fn.apply(context, args);
      lastTime = now;
    }
  };
}

// 使用
var handleScroll = throttle(function() {
  console.log('滚动位置:', window.scrollY);
}, 200);

window.addEventListener('scroll', handleScroll);
```

**防抖 vs 节流的区别：**

- 防抖：将多次执行合并为最后一次执行（如搜索框输入）
- 节流：将高频执行降频为固定间隔执行（如滚动、resize）



#### 场景三：柯里化（Currying）

将接受多个参数的函数转换成一系列接受一个参数的函数，并返回接受余下参数的新函数。

```javascript
// 通用柯里化函数
function curry(fn) {
  var arity = fn.length;  // 原函数的参数个数
  
  return function curried() {
    var args = Array.prototype.slice.call(arguments);
    
    if (args.length >= arity) {
      return fn.apply(null, args);
    } else {
      return function() {
        var rest = Array.prototype.slice.call(arguments);
        return curried.apply(null, args.concat(rest));
      };
    }
  };
}

// 使用
function add(a, b, c) {
  return a + b + c;
}

var curriedAdd = curry(add);
console.log(curriedAdd(1)(2)(3));  // 6
console.log(curriedAdd(1, 2)(3));  // 6
console.log(curriedAdd(1)(2, 3));  // 6
```

柯里化的本质就是利用闭包**累积参数**，直到参数满足要求才执行原函数。

#### 场景四：模块模式（Module Pattern）

利用闭包创建私有变量和特权方法，模拟封装。

```javascript
var counterModule = (function() {
  // 私有变量（外部无法直接访问）
  var count = 0;
  
  // 私有方法
  function validate(value) {
    return typeof value === 'number' && value > 0;
  }
  
  // 暴露的公共 API
  return {
    increment: function() {
      count++;
      return count;
    },
    decrement: function() {
      count--;
      return count;
    },
    getCount: function() {
      return count;
    },
    reset: function() {
      count = 0;
    }
  };
})();

console.log(counterModule.getCount()); // 0
counterModule.increment();
counterModule.increment();
console.log(counterModule.getCount()); // 2
console.log(counterModule.count);      // undefined — 私有变量不可访问
counterModule.reset();
console.log(counterModule.getCount()); // 0
```

这是 ES6 模块出现之前，JavaScript 实现模块化和私有封装的标准方式。

## 四、闭包的内存泄漏问题及解决



### 4.1 为什么会内存泄漏？

正常情况下，函数执行完毕后，其执行上下文出栈，活动对象（AO）被垃圾回收。但如果内部函数形成闭包并持有外部变量的引用，这些变量就**不会被回收**，持续占用内存。

```javascript
function createHeavyClosure() {
  var bigData = new Array(1000000).fill('data'); // 占用大量内存
  
  return function() {
    console.log(bigData.length);
  };
}

var leak = createHeavyClosure();
// bigData 不会被回收，因为 leak 闭包持有引用
```

如果 `leak` 长期存在且不再使用，`bigData` 就一直占用内存，这就是闭包导致的内存泄漏。

### 4.2 常见泄漏场景



#### 场景一：循环中创建闭包引用 DOM

```javascript
// 有问题的写法
for (var i = 0; i < elements.length; i++) {
  elements[i].addEventListener('click', function() {
    console.log(elements[i].id); // 闭包持有 elements 和 i 的引用
  });
}
```



#### 场景二：定时器/事件监听器未清理

```javascript
function setup() {
  var resource = getData(); // 大对象
  
  setInterval(function() {
    console.log(resource); // 闭包持有 resource
  }, 1000);
  // 没有保存 interval ID，无法清除
}
```



#### 场景三：意外的全局变量

```javascript
function foo() {
  var data = '敏感数据';
  leak = function() { return data; }; // 意外创建全局变量，闭包永不释放
}
foo();
```



### 4.3 解决方案



#### 方案一：手动解除引用

```javascript
function createClosure() {
  var bigData = new Array(1000000).fill('data');
  
  return {
    use: function() { console.log(bigData.length); },
    destroy: function() {
      bigData = null; // 解除引用，等待 GC 回收
    }
  };
}

var obj = createClosure();
obj.use();
obj.destroy(); // 使用完毕后手动释放
obj = null;    // 解除对闭包本身的引用
```



#### 方案二：及时清除定时器和事件监听器

```javascript
function setup() {
  var resource = getData();
  
  var timerId = setInterval(function() {
    console.log(resource);
  }, 1000);
  
  // 返回清理函数
  return function cleanup() {
    clearInterval(timerId);
    resource = null;
  };
}

var cleanup = setup();
// 不再需要时
cleanup();
```

事件监听器同理，使用 `removeEventListener` 移除。

#### 方案三：使用 IIFE 限制作用域

```javascript
// 循环中使用立即执行函数切断闭包引用
for (var i = 0; i < elements.length; i++) {
  (function(index) {
    elements[index].addEventListener('click', function() {
      console.log(elements[index].id);
    });
  })(i);
}

// 更现代的方式：使用 let（块级作用域）
for (let i = 0; i < elements.length; i++) {
  elements[i].addEventListener('click', function() {
    console.log(elements[i].id);
  });
}
```



#### 方案四：使用 WeakMap/WeakRef（ES6+）

```javascript
// WeakMap 的键是弱引用，不阻止垃圾回收
var cache = new WeakMap();

function process(element) {
  if (!cache.has(element)) {
    cache.set(element, computeHeavyData(element));
  }
  return cache.get(element);
}
// element 被移除后，WeakMap 中的条目自动被回收
```



#### 方案五：ES6 块级作用域减少闭包

`let` 和 `const` 提供块级作用域，减少了因 `var` 函数作用域导致的意外闭包：

```javascript
// var 导致所有回调共享同一个 i
for (var i = 0; i < 3; i++) {
  setTimeout(function() { console.log(i); }, 100); // 输出 3, 3, 3
}

// let 每次迭代创建新的绑定
for (let i = 0; i < 3; i++) {
  setTimeout(function() { console.log(i); }, 100); // 输出 0, 1, 2
}
```



### 4.4 内存泄漏排查工具

- **Chrome DevTools Memory 面板**：录制堆快照，对比快照查找未释放的对象。
- **Performance 面板**：录制运行过程，观察内存曲线是否持续上升。
- `--inspect` **+ Node.js inspector**：服务端 Node 应用的内存分析。

## 面试总结



闭包是指有权访问另一个函数作用域中变量的函数。闭包的产生条件为: 
1. **函数嵌套**：存在内层函数和外层函数的嵌套关系。
2. **引用自由变量**：内层函数引用了外层函数的局部变量（自由变量）。
3. **外部调用**：内层函数在其外层函数之外被调用（通常通过 return、赋值给外部变量、作为回调等方式）

闭包的应用场景有：
1. 防抖（Debounce），在事件被触发 n 秒后再执行回调，如果 n 秒内又被触发，则重新计时。将多次执行合并为最后一次执行（如搜索框输入）
2. 节流（Throttle）规定在一个单位时间内，只能触发一次函数。如果这个单位时间内触发多次，只有一次生效。将高频执行降频为固定间隔执行（如滚动、resize）
3. 柯里化（Currying）将接受多个参数的函数转换成一系列接受一个参数的函数，并返回接受余下参数的新函数。
4.模块模式（Module Pattern）利用闭包创建私有变量和特权方法，模拟封装。

闭包导致内存泄露的原因:
正常情况下，函数执行完毕后，其执行上下文出栈，活动对象（AO）被垃圾回收。但如果内部函数形成闭包并持有外部变量的引用，这些变量就**不会被回收**，持续占用内存。
解决方案有：使用ES6中`let` 和 `const` 提供的块级作用域，减少了因 `var` 函数作用域导致的意外闭包
