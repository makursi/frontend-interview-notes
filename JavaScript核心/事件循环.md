# 事件循环

# JavaScript 事件循环（Event Loop）详解

## 一、为什么需要事件循环？

JavaScript 是**单线程**语言，同一时间只能执行一段代码。但浏览器/Node 又需要处理网络请求、定时器、用户交互等异步操作，于是就有了 **事件循环（Event Loop）**——它是 JS 实现非阻塞异步执行的核心机制。

核心思想：**调用栈（Call Stack）执行同步代码，异步任务交给宿主环境（浏览器/Node），完成后把回调放入任务队列，调用栈清空后再从队列里取任务执行。**

---

## 二、宏任务（Macrotask）与 微任务（Microtask）

异步任务被分成两类，它们进入不同的队列，优先级也不同。

### 宏任务（Macrotask / Task）


| 来源   | 具体 API                                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------- |
| 浏览器  | `setTimeout`、`setInterval`、`setImmediate`（IE/Node）、`requestAnimationFrame`、I/O 操作、UI 渲染、UI 事件（click/scroll 等） |
| Node | `setTimeout`、`setInterval`、`setImmediate`、I/O（文件/网络）、close 回调                                                 |


> 每次事件循环只从宏任务队列取**一个**任务执行。



### 微任务（Microtask / Job）


| 来源   | 具体 API                                                                       |
| ---- | ---------------------------------------------------------------------------- |
| 浏览器  | `Promise.then/catch/finally`、`queueMicrotask()`、`MutationObserver`           |
| Node | `Promise.then/catch/finally`、`queueMicrotask()`、`process.nextTick`（特殊，优先级更高） |


> 微任务队列会在当前宏任务结束后**全部清空**（包括执行过程中新产生的微任务）。

---



## 三、浏览器中的执行顺序

标准流程（一个完整的 tick）：

```
1. 执行同步代码（调用栈中的任务）
        ↓
2. 清空微任务队列（执行所有微任务，包括新产生的）
        ↓
3. 浏览器判断是否需要渲染（requestAnimationFrame → 布局 → 绘制）
        ↓
4. 取下一个宏任务执行（回到第 1 步）
```



### 经典示例

```javascript
console.log('1. 同步开始');

setTimeout(() => {
  console.log('3. 宏任务 setTimeout');
}, 0);

Promise.resolve()
  .then(() => {
    console.log('2. 微任务 Promise.then 1');
  })
  .then(() => {
    console.log('2.5. 微任务 Promise.then 2（微任务中产生的微任务）');
  });

console.log('1.5. 同步结束');
```

**输出顺序：**

```
1. 同步开始
1.5. 同步结束
2. 微任务 Promise.then 1
2.5. 微任务 Promise.then 2（微任务中产生的微任务）
3. 宏任务 setTimeout
```

**关键点：**

- 同步代码先全部执行完。
- 微任务在每个宏任务结束后、渲染前**一次性清空**，所以 `then` 里再 `then` 也会在本轮执行。
- `setTimeout` 即使延迟为 0，也属于宏任务，排在微任务之后。



### 渲染时机

微任务清空后，浏览器会判断是否需要更新界面。`requestAnimationFrame` 在渲染前执行，属于宏任务范畴但紧贴渲染。如果微任务队列一直有新任务加入（死循环式添加），渲染会被**阻塞**，页面卡死。

## 四、Node 中的 Event Loop

Node 的事件循环基于 **libuv**，分为 **6 个阶段**，每个阶段有自己的回调队列：

```
   ┌───────────────────────────┐
┌─>│           timers          │  执行 setTimeout / setInterval 到期回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │     pending callbacks     │  执行延迟到下一轮的 I/O 回调（如 TCP 错误）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │       idle, prepare       │  内部使用（idle/prepare 句柄）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │           poll            │  轮询 I/O：执行已完成的 I/O 回调；可能阻塞等待
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │           check           │  执行 setImmediate 回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
└──┤      close callbacks      │  执行 close 事件回调（如 socket.on('close')）
   └───────────────────────────┘
```



### 各阶段说明


| 阶段                    | 作用                                                           |
| --------------------- | ------------------------------------------------------------ |
| **timers**            | 检查 `setTimeout` / `setInterval`，到期的回调按顺序执行                   |
| **pending callbacks** | 执行上一轮未完成的 I/O 回调（系统级错误回调等）                                   |
| **idle, prepare**     | Node 内部使用，开发者一般不接触                                           |
| **poll**              | 核心阶段：执行已就绪的 I/O 回调；如果队列为空且没有 `setImmediate`，会在此阻塞等待新的 I/O 事件 |
| **check**             | 执行 `setImmediate` 的回调                                        |
| **close callbacks**   | 执行关闭类回调，如 `socket.on('close', ...)`                          |




### Node 中的微任务与 `process.nextTick`

Node 在**每个阶段切换之间**（即每个阶段的队列清空后），都会清空微任务队列。而微任务内部又分优先级：

```
process.nextTick 队列  →  Promise / queueMicrotask 队列
（更高优先级）              （普通微任务）
```

也就是说，`process.nextTick` 的回调**优先于** `Promise.then` 执行。

### Node 示例

```javascript
setTimeout(() => console.log('timer1'), 0);
setImmediate(() => console.log('immediate1'));

Promise.resolve().then(() => console.log('promise1'));
process.nextTick(() => console.log('nextTick1'));

console.log('同步');
```

**输出（典型情况）：**

```
同步
nextTick1
promise1
timer1
immediate1
```

> 注意：`setTimeout(fn, 0)` 和 `setImmediate` 的执行顺序在主模块中**不固定**（取决于事件循环进入时机和系统性能），但如果都在一个 I/O 回调内，`setImmediate` 总是先于 `setTimeout`（因为 I/O 回调在 poll 阶段，下一个阶段就是 check，而 timers 要等下一轮）。

## 五、浏览器 vs Node Event Loop 核心区别


| 对比项                  | 浏览器           | Node（libuv）                         |
| -------------------- | ------------- | ----------------------------------- |
| **模型结构**             | 宏任务队列 + 微任务队列 | 6 个阶段，每个阶段有独立队列                     |
| **宏任务执行**            | 每轮取 1 个宏任务    | 每个阶段执行该阶段队列的**所有**回调（有数量上限）         |
| **微任务清空时机**          | 每个宏任务之后       | 每个**阶段切换**之间                        |
| **微任务优先级**           | 同一队列，FIFO     | `process.nextTick` > `Promise.then` |
| **渲染**               | 有 UI 渲染步骤     | 无渲染概念                               |
| **setImmediate**     | 非标准（仅 IE 支持）  | 标准 API，在 check 阶段执行                 |
| **process.nextTick** | 不存在           | Node 独有，优先级最高的微任务                   |




### 最容易混淆的一点

- **浏览器**：一个宏任务 → 清空所有微任务 → 可能渲染 → 下一个宏任务
- **Node**：一个阶段的所有宏任务 → 清空所有微任务 → 下一个阶段

所以在 Node 中，同一个阶段里的多个回调之间**不会**插入微任务，只有阶段切换时才清空微任务队列。

## 面试总结

### JavaScript的异步模型是什么？

JavaScript 是一门单线程语言，同一时间只能执行一个任务。但浏览器需要同时处理网络请求、定时器、DOM 事件等耗时操作，因此采用了异步模型。当同步代码在主线程执行完成后，Event Loop 会不断监控调用栈和检查任务队列，把已经完成的异步任务回调重新放回主线程执行，从而实现单线程下的异步能力。

在浏览器或Nodejs环境下，JS异步模型主要由以下几部分组成：

- **调用栈**: JS同步代码执行优化的地方。
- **堆**: 对象内存分配区域。
- **Web API线程池**: 浏览器或底层库提供的异步能力,包含:setTimeout、setInterval、DOM 事件、fetch/XMLHttpRequest、I/O 等。
- **宏任务队列**: 存放宏任务
- **微任务队列**: 存放微任务
- **事件循环**: 不断检查调用栈是否为空，然后决定从哪个队列取任务执行,然后将任务队列中的执行回调推入到调用栈中。

### 怎么区分宏任务和微任务?

宏任务就相当于一次完整的 JavaScript 执行任务, 它包括：
- script整体代码
- setTimeout/setInterval
- I/O操作
- UI渲染操作

微任务是必须在当前宏任务结束后立即执行的任务。它包括:
- Promise.then / .catch / .finally,与Promise对象相关的方法
- MutationObserver(监听DOM变化的API，当同步代码执行完毕后，立即执行回调)
- queueMicrotask(把一个函数放入微任务队列中执行。)
- process.nextTick（在Nodejs当中优先级最高,非官方规范API）

### 事件循环的过程是什么？

当我们从一段复杂的JavaScript代码开始时, 整个 `<script>`  会作为第一个宏任务进入 Event Loop 开始执行。

1. 所有同步代码依次进入**调用栈（Call Stack）** 执行；
2. 执行过程中如果遇到`Promise.then`、`queueMicrotask`、`MutationObserver` 等异步操作,会将对应的回调加入**微任务队列（Microtask Queue）;**
3. 如果遇到 `setTimeout`、`setInterval`、`DOM`  事件、网络请求等异步操作，则由浏览器相应模块处理，待条件满足后再将回调加入**宏任务队列（Task Queue）**。
4. 当前宏任务中的所有同步代码执行完毕，**调用栈**清空后，Event Loop 会立即进入 **Microtask Checkpoint（微任务检查点）**，按照先进先出（FIFO）的顺序执行微任务队列中的所有任务；如果执行微任务期间又产生了新的微任务，则继续执行，直到微任务队列完全清空。
5. 随后，浏览器获得一次**渲染机会（Rendering Opportunity）**，根据需要完成样式计算、布局、绘制和合成等渲染工作。渲染结束后，Event Loop 再从宏任务队列中取出下一个宏任务执行，并重复以上流程。

总结流程为: **执行第一个Script宏任务 → 执行其中所有同步代码 → 清空所有微任务 → 浏览器有机会进行渲染 → 执行下一个宏任务 → 循环往复。**
