## 一、选择器优先级（Specificity）

### 1.1 优先级总览

当多个 CSS 规则同时命中同一个元素的同一个属性时，浏览器通过**层叠算法（Cascade）**决定最终生效的值。优先级从高到低为：

| 层级 | 类型 | 示例 | 权重记法 |
| --- | --- | --- | --- |
| 1 | `!important` 声明 | `color: red !important` | 凌驾于一切之上 |
| 2 | 行内样式（inline style） | `style="color: red"` | `1-0-0-0` |
| 3 | ID 选择器 | `#header` | `1-0-0` |
| 4 | 类 / 属性 / 伪类选择器 | `.btn`、`[type="text"]`、`:hover` | `0-1-0` |
| 5 | 标签 / 伪元素选择器 | `div`、`p`、`::before` | `0-0-1` |
| 6 | 通配选择器 | `*` | `0-0-0`（不增加权重） |

> 
> 来源：MDN 明确指出，行内样式可视为 `1-0-0-0`，始终覆盖作者样式表中的普通声明；唯一能覆盖行内样式的是 `!important`。

### 1.2 三列计算法（核心）

MDN 现行规范采用 **ID - CLASS - TYPE** 三列计数法（旧版教材常用 `a,b,c,d` 四列，本质一致）：

- **ID 列**：统计选择器中 ID 选择器的数量，每个 `+1-0-0`
- **CLASS 列**：统计类选择器、属性选择器、伪类的数量，每个 `+0-1-0`
- **TYPE 列**：统计标签选择器、伪元素的数量，每个 `+0-0-1`

比较时**从左到右逐列比较**，某一列分出胜负即停止，后面列不再比较。这意味着：**无论多少个 class 也拼不过一个 id**。

```
/* 计算示例 */
#nav .item a:hover::after
/*  ID: 1 (#nav)
    CLASS: 2 (.item, :hover)
    TYPE: 2 (a, ::after)
    权重 = 1-2-2  */

div.container .box[data-active="true"] span
/*  ID: 0
    CLASS: 3 (.container, .box, [data-active="true"])
    TYPE: 2 (div, span)
    权重 = 0-3-2  */
```

### 1.3 `!important` 的特殊性

`!important` 严格来说**不属于优先级计算**，但它直接与层叠交互：在同一来源、同一 cascade layer 内，带 `!important` 的声明无论选择器权重多低都会胜出。如果两个都带 `!important`，才回到优先级比较。

**最佳实践**：MDN 明确将用 `!important` 覆盖优先级视为**反模式（bad practice）**，建议改用 `@layer` 级联层来管理第三方样式覆盖。

### 1.4 容易忽略的细节

- **通配符 `*`、`:where()`**：权重为 `0-0-0`，能匹配元素但不增加优先级。`:where()` 专门用于"写得很具体但不提升权重"的场景。
- **`:is()`、`:not()`、`:has()`**：本身不增加权重，但其参数列表中**优先级最高的那个选择器**的会计入。例如 `:is(#id, .class)` 的权重等同于 `#id`（`1-0-0`）。
- **组合符**（`+`、`>`、`~`、空格、`||`）：不增加任何权重。
- **优先级相同时**：后声明的规则胜出（源码顺序）。
- **直接命中 vs 继承**：直接命中元素的规则永远优先于从祖先继承来的样式，无论继承规则的选择器权重多高。

## 二、rem / em / vw / vh / % 的区别

这五个都是**相对长度单位**，但各自的"参考基准"完全不同。W3C CSS Values and Units Module Level 3/4 给出了明确定义。

### 2.1 逐个拆解

| 单位 | 全称 / 含义 | 相对基准 | 关键特性 |
| --- | --- | --- | --- |
| `em` | 相对于字号 | **用于 `font-size` 时**：相对父元素的 font-size；**用于其他属性时**：相对元素自身的 font-size | 会产生"嵌套放大"效应 |
| `rem` | root em | **根元素（`<html>`）的 font-size** | 全文档统一基准，不会嵌套累积 |
| `vw` | viewport width | **视口宽度的 1%** | `100vw` = 视口完整宽度 |
| `vh` | viewport height | **视口高度的 1%** | `100vh` = 视口完整高度 |
| `%` | 百分比 | **取决于具体属性**：width 相对父元素宽度；font-size 相对父元素 font-size；margin/padding 相对父元素宽度 | 不是统一基准，需逐属性判断 |

### 2.2 `em` 的"双重身份"（重点易错点）

MDN 明确指出：`em` 用于 `font-size` 属性时，表示"父元素的 font-size"；用于其他属性（如 `width`、`margin`、`padding`）时，表示"元素自身的 font-size"。

```
.parent { font-size: 20px; }
.child  { font-size: 1.5em; }  /* = 30px，相对父元素 20px */
.child  { width: 2em; }        /* = 60px，相对自身 font-size 30px */
```

嵌套列表中每层 `font-size: 1.3em` 会导致字号逐层放大（1.3 → 1.69 → 2.197...），这是 `em` 最经典的坑。

### 2.3 `rem` 的优势

`rem` 始终相对 `<html>` 的 font-size（浏览器默认 16px），因此无论嵌套多深，`1.5rem` 永远等于 `24px`。这使得 `rem` 成为**响应式排版和间距**的首选单位——只需修改 `html { font-size }` 即可全局缩放。

常见实践：

```
html { font-size: 62.5%; }  /* 16px × 62.5% = 10px，方便计算 */
body { font-size: 1.6rem; } /* = 16px */
```

### 2.4 `vw` / `vh` 的特点

- `1vw` = 视口宽度的 1%。视口宽 800px 时，`50vw` = 400px。
- 不受父元素影响，直接相对浏览器可视区域。
- 移动端注意：`100vh` 在移动端浏览器中可能因地址栏伸缩导致布局跳动，可考虑用 `100dvh`（动态视口高度）替代。
- 衍生单位：`vmin`（宽高中较小者的 1%）、`vmax`（较大者的 1%）。

### 2.5 `%` 的"属性依赖"

百分比没有统一基准，**每个 CSS 属性自己定义百分比相对什么**：

- `width: 50%` → 父元素 content width 的 50%
- `font-size: 80%` → 父元素 font-size 的 80%
- `margin-top: 10%` → 父元素**宽度**的 10%（不是高度！这是经典坑）
- `line-height: 150%` → 自身 font-size 的 150%
- `height: 50%` → 父元素 height 的 50%（前提是父元素有明确高度）

### 2.6 选型建议

- **字号**：优先 `rem`（全局可控），需要组件内联动缩放时用 `em`
- **布局宽度**：`%`（流式布局）或 `vw`（全屏相关）
- **全屏元素 / 英雄区**：`vw` / `vh`
- **间距**：`rem` 为主，需要与字号联动的内边距用 `em`

## 三、CSS 动画（transition、animation、@keyframes）

CSS 提供两套动画体系：**transition（过渡）** 是"隐式动画"，**animation + @keyframes** 是"显式关键帧动画"。

### 3.1 transition —— 两状态之间的平滑过渡

transition 的本质是：**当某个 CSS 属性的值发生变化时，让这个变化在指定时间内平滑完成，而不是瞬间切换**。MDN 称之为"隐式过渡（implicit transitions）"，因为起始和结束之间的中间状态由浏览器自动计算。

**四个子属性：**

```
transition: <property> <duration> <timing-function> <delay>;
```

| 属性 | 作用 | 示例 |
| --- | --- | --- |
| `transition-property` | 要过渡的属性名（`all` 表示所有可动画属性） | `opacity`, `transform` |
| `transition-duration` | 过渡持续时间 | `0.3s`, `300ms` |
| `transition-timing-function` | 缓动函数（加速度曲线） | `ease`, `linear`, `cubic-bezier(...)` |
| `transition-delay` | 延迟多久后开始过渡 | `0.1s` |

```
.btn {
  background: #3498db;
  transition: background 0.3s ease, transform 0.2s ease-out;
}
.btn:hover {
  background: #2980b9;
  transform: translateY(-2px);
}
```

**特点与限制：**

- 需要一个**触发条件**（`:hover`、`:focus`、类名切换、JS 修改样式等），不能自动播放
- 只有**起始态和结束态**两个关键帧，无法定义中间状态
- 不能循环播放（触发一次执行一次）
- 并非所有属性都可过渡，`display`、`position` 等不可动画（新版规范已支持 `display` 的离散过渡，需 `transition-behavior: allow-discrete`）

### 3.2 animation + @keyframes —— 显式关键帧动画

`@keyframes` 用于定义动画序列中**各个时间点的样式**，`animation` 属性将这个序列应用到元素上并控制播放行为。

**定义关键帧：**

```
@keyframes slideIn {
  from { transform: translateX(-100%); opacity: 0; }   /* 等价于 0% */
  60%  { transform: translateX(10px); opacity: 1; }
  to   { transform: translateX(0); opacity: 1; }        /* 等价于 100% */
}
```

`from` = `0%`，`to` = `100%`，中间可以写任意百分比节点。

**animation 简写（9 个子属性）：**

```
animation: <name> <duration> <timing-function> <delay> 
           <iteration-count> <direction> <fill-mode> <play-state>;
```

| 属性 | 作用 | 常用值 |
| --- | --- | --- |
| `animation-name` | 关联的 @keyframes 名称 | `slideIn` |
| `animation-duration` | 单次动画时长 | `1s` |
| `animation-timing-function` | 缓动函数 | `ease`, `linear`, `steps(4)` |
| `animation-delay` | 开始前延迟 | `0.5s` |
| `animation-iteration-count` | 播放次数 | `1`, `infinite` |
| `animation-direction` | 播放方向 | `normal`, `reverse`, `alternate` |
| `animation-fill-mode` | 动画前后的样式保留 | `none`, `forwards`, `backwards`, `both` |
| `animation-play-state` | 播放/暂停 | `running`, `paused` |

```
.card {
  animation: slideIn 0.8s cubic-bezier(0.25, 0.46, 0.45, 0.94) 0.1s both;
}

.loading {
  animation: spin 1s linear infinite;  /* 无限循环旋转 */
}
```

### 3.3 transition vs animation 对比

| 维度 | transition | animation |
| --- | --- | --- |
| 关键帧数量 | 2 个（起→终） | 任意多个（0%~100%） |
| 触发方式 | 需要状态变化触发 | 可自动播放 |
| 循环 | 不支持 | 支持 `infinite` |
| 中间状态控制 | 无 | 精确控制每个百分比 |
| 暂停/回放 | 间接 | `animation-play-state` |
| 适用场景 | hover 反馈、状态切换 | 加载动画、入场动画、复杂特效 |
| 性能 | 轻量 | 相对较重 |

### 3.4 性能建议

MDN 在 animation 文档中明确提示：**动画化盒模型属性（width、height、margin 等）非常消耗 CPU**，应优先动画 `transform` 和 `opacity`——这两个属性可以由 GPU 合成层处理，不触发重排（reflow）。

## 四、移动端 1px 问题及解决方案

### 4.1 问题根源

移动端 Retina 屏的**设备像素比（DPR, Device Pixel Ratio）**大于 1：

- DPR = 2：1 个 CSS 像素 = 2 × 2 个物理像素
- DPR = 3：1 个 CSS 像素 = 3 × 3 个物理像素（如 iPhone  Plus/Pro 系列）

当你写 `border: 1px solid #ccc` 时，在 DPR=2 的屏幕上实际渲染为 **2 个物理像素宽**，视觉上比设计稿的"1 物理像素细线"粗一倍，这就是 1px 问题。

### 4.2 解决方案

#### 方案一：transform: scale() 缩放（最常用，推荐）

用伪元素画边框，再通过 `transform: scaleY(0.5)` 纵向压缩到一半。

```
/* 下边框 1px 细线 */
.border-bottom {
  position: relative;
}
.border-bottom::after {
  content: '';
  position: absolute;
  left: 0;
  bottom: 0;
  width: 100%;
  height: 1px;
  background-color: #ccc;
  transform: scaleY(0.5);          /* DPR=2 时压缩到 0.5px */
  transform-origin: 0 0;
}

/* 配合媒体查询适配不同 DPR */
@media (-webkit-min-device-pixel-ratio: 3) {
  .border-bottom::after {
    transform: scaleY(0.333);      /* DPR=3 时压缩到 1/3 */
  }
}
```

**全边框版本**（伪元素放大 2 倍再整体缩小）：

```
.border-1px {
  position: relative;
}
.border-1px::after {
  content: '';
  position: absolute;
  top: 0; left: 0;
  width: 200%;
  height: 200%;
  border: 1px solid #ccc;
  transform: scale(0.5);
  transform-origin: left top;
  pointer-events: none;
}
```

优点：效果好、兼容性佳；缺点：圆角边框处理较麻烦，需要额外调整。

#### 方案二：border-image

准备一张 2px 高的图片（上 1px 透明、下 1px 为边框色），通过 `border-image` 拉伸：

```
.border-bottom {
  border-bottom: 1px solid transparent;
  border-image: url('border-image.png') 2 0 stretch;
}
```

优点：实现简单；缺点：需要切图，改颜色不方便。

#### 方案三：box-shadow 模拟

利用 `box-shadow` 的第四个参数（spread radius）可以实现亚像素渲染：

```
.border-1px {
  box-shadow: 0 0 0 0.5px #ccc;  /* 部分浏览器支持 0.5px 的阴影扩散 */
}
```

优点：代码极简；缺点：兼容性不如 transform 方案，部分安卓机型渲染不一致。

#### 方案四：直接写 0.5px

iOS Safari 从 iOS 8 开始支持 `border: 0.5px`，但安卓端兼容性差，不建议单独使用。

#### 方案五：viewport + rem 动态缩放（淘宝 flexible 方案）

通过 JS 动态设置 `<meta name="viewport">` 的 `initial-scale = 1 / DPR`，让 1px CSS 直接对应 1 物理像素：

```
<!-- DPR=2 时 -->
<meta name="viewport" content="initial-scale=0.5, maximum-scale=0.5, minimum-scale=0.5, user-scalable=no">
```

配合 JS 动态计算根元素 font-size 实现 rem 适配。这是早期移动端适配的经典方案，但现在随着 `vw/vh` 的普及和浏览器对小数像素的支持改善，已较少新项目使用。

## 面试总结

选择器优先级计算按照层叠算法决定生效的值,优先级从高到底为： 

1.`!important` 声明,凌驾于一切之上

2. 行内样式，权重为1-0-0-0；

3. ID选择器，权重为0-1-0-0;

4. 类 / 属性 / 伪类选择器,权重为0-0-1-0;

5. 标签/伪元素选择器,权重为0-0-0-1;

6. 通配符选择器,权重为0-0-0-0(不增加权重);
