# 盒模型
---

## 一、盒模型的基本构成

在 CSS 中，所有元素都被"盒子"包围。一个**区块盒子（block box）** 由内到外包含四个部分：

| 层级 | 名称 | 说明 | 控制属性 |
| --- | --- | --- | --- |
| 最内层 | **内容盒子（content box）** | 显示内容的区域 | `width` / `height` |
| 第二层 | **内边距盒子（padding box）** | 内容周围的空白，背景会延伸至此 | `padding` |
| 第三层 | **边框盒子（border box）** | 包住内容和内边距 | `border` |
| 最外层 | **外边距盒子（margin box）** | 盒子与其他元素之间的空白，**透明不可见** | `margin` |

> 
> **关键点**：`margin` 不计入盒子的实际大小——盒子的可见面积止于边框，外边距只影响盒子外部占据的空间。

## 二、标准盒模型 vs IE 盒模型

这是两种计算元素总宽高的方式，核心区别在于 **`width`/`height` 到底包含了什么**。

### 1. 标准盒模型（`content-box`，W3C 标准，默认值）

`width` 和 `height` **只定义内容区**的尺寸，`padding` 和 `border` 会**额外叠加**到最终渲染尺寸上。

**计算公式**：

- 元素总宽度 = `width` + `padding-left` + `padding-right` + `border-left` + `border-right`
- 元素总高度 = `height` + `padding-top` + `padding-bottom` + `border-top` + `border-bottom`

**示例**：

```
.box {
  width: 350px;
  height: 150px;
  padding: 25px;
  border: 5px solid black;
  margin: 10px;
}
```

实际占用宽度 = 350 + 25×2 + 5×2 = **410px**
实际占用高度 = 150 + 25×2 + 5×2 = **210px**

### 2. IE 盒模型（`border-box`，替代盒模型）

`width` 和 `height` **已经包含了内容、内边距和边框**，设置多少就是多少，无需额外计算。内容区的实际宽度 = `width` - `padding` - `border`。

**计算公式**：

- 元素总宽度 = `width`（已包含 padding + border）
- 元素总高度 = `height`（已包含 padding + border）

同样的 CSS，使用 `border-box` 后：
实际占用宽度 = **350px**，实际占用高度 = **150px**
内容区宽度 = 350 - 25×2 - 5×2 = **290px**

> 
> 这种模型是 IE 在 Quirks（怪异）模式下的传统行为，因此得名"IE 盒模型"。

### 对比总结

| 对比项 | `content-box`（标准） | `border-box`（IE/替代） |
| --- | --- | --- |
| `width` 含义 | 仅内容区宽度 | 内容 + padding + border |
| 加 padding/border 后 | 盒子会变大 | 盒子不变，内容区缩小 |
| 布局直觉 | 需要心算叠加 | 设置即所得，更直观 |
| 适用场景 | 精确控制内容尺寸 | 响应式布局、组件开发 |

## 三、`box-sizing` 属性

`box-sizing` 定义了浏览器**如何计算元素的总宽度和总高度**，是切换两种盒模型的开关。

### 语法

```
box-sizing: content-box | border-box;
```

| 值 | 说明 |
| --- | --- |
| `content-box` | 默认值，标准盒模型 |
| `border-box` | 替代盒模型（IE 模型） |

- **初始值**：`content-box`
- **是否继承**：否
- **动画类型**：离散值（不可过渡动画）

### 全局重置为 `border-box`（业界最佳实践）

由于 `border-box` 更符合直觉，大多数项目会在全局统一设置：

```
/* 经典全局重置方案 */
html {
  box-sizing: border-box;
}
*, *::before, *::after {
  box-sizing: inherit;
}
```

这样所有元素默认使用 `border-box`，同时允许某些组件通过显式设置 `box-sizing: content-box` 来回退。

> 
> **注意**：如果你在编写第三方共享组件库，需谨慎——如果使用者的页面没有全局设置 `border-box`，你的组件尺寸可能与预期不符。

## 四、margin 折叠（外边距塌陷）

块级元素的**上下外边距**有时会合并（折叠）为一个外边距，其大小取**单个外边距中的最大值**（相等时取该值），这就是 margin 折叠。

### 三种基本场景

#### 场景 1：相邻兄弟元素

两个相邻块级兄弟元素的上下外边距会折叠。

```
<p>第一段</p>
<p>第二段</p>
```

```
p:first-child { margin-bottom: 50px; }
p:last-child  { margin-top: 30px; }
```

**实际间距 = max(50px, 30px) = 50px**，而非 80px。

#### 场景 2：父元素与子元素（无内容分隔）

当父元素和其第一个/最后一个子元素之间没有 `border`、`padding`、行内内容或 `clearance` 分隔时，外边距会合并并"溢出"到父元素外部。

- 父元素的 `margin-top` 与第一个子元素的 `margin-top` 合并
- 父元素的 `margin-bottom` 与最后一个子元素的 `margin-bottom` 合并

```
<div class="parent">
  <div class="child">内容</div>
</div>
```

```
.parent { margin-top: 20px; }
.child  { margin-top: 50px; }
```

结果：父元素顶部实际外边距变为 **50px**（子元素的 margin 穿透到了父元素外面）。

#### 场景 3：空块元素

如果一个块级元素没有 `border`、`padding`、行内内容、`height` 或 `min-height`，它的 `margin-top` 和 `margin-bottom` 会自身折叠。

```
.empty { margin-top: 30px; margin-bottom: 50px; }
```

该空元素实际只贡献 **50px** 的外边距（上下合并）。

### 折叠的计算规则

| 情况 | 折叠后的值 |
| --- | --- |
| 两个正边距 | 取较大值 `max(a, b)` |
| 两个负边距 | 取较小值（离 0 最远）`min(a, b)` |
| 一正一负 | 正边距 + 负边距（即从正值中减去负值的绝对值） |

### 不会发生折叠的情况

- **浮动元素**（`float` 不为 `none`）的外边距永不折叠
- **绝对定位元素**（`position: absolute/fixed`）的外边距永不折叠
- `display: flex` 或 `display: grid` 容器内的**子元素**之间不会折叠
- 只有**垂直方向**会折叠，水平方向不会

## 五、BFC（块级格式化上下文）

### 什么是 BFC

**BFC（Block Formatting Context）** 是 Web 页面可视化 CSS 渲染的一部分，是**块级盒子布局发生的区域**，也是浮动元素与其他元素交互的区域。可以把它理解为一个**独立的布局环境**——内部元素的布局不会影响外部，反之亦然。

### 创建 BFC 的常见方式

以下任意一种方式都会创建新的 BFC：

| 方式 | 说明 |
| --- | --- |
| 根元素 `<html>` | 整个文档本身就是一个 BFC |
| `float: left/right` | 浮动元素 |
| `position: absolute/fixed` | 绝对/固定定位元素 |
| `display: inline-block` | 行内块元素 |
| `display: table-cell` / `table-caption` | 表格单元格/标题 |
| `display: flow-root` | **专门用于创建 BFC，无副作用**（推荐） |
| `overflow` 不为 `visible` / `paint` | 如 `overflow: auto/hidden/scroll` |
| `display: flex` / `grid` 的直接子元素 | 弹性项/网格项（本身非 flex/grid/table 容器） |
| `contain: layout/content/paint` | 包含布局的元素 |

### BFC 的三大特性

1. **包含内部浮动**：BFC 会包裹住内部的浮动元素，解决父元素高度塌陷（"清除浮动"）。
2. **排除外部浮动**：BFC 元素不会与外部浮动元素重叠，可实现自适应两栏布局。
3. **阻止外边距折叠**：BFC 内部的 margin 不会与外部的 margin 折叠。

### 用 BFC 解决 margin 折叠

#### 解决父子 margin 穿透

给父元素创建 BFC，即可阻止子元素的 margin 溢出：

```
.parent {
  /* 以下任选其一创建 BFC */
  overflow: hidden;    /* 方法1：可能裁剪内容 */
  display: flow-root;  /* 方法2：推荐，无副作用 */
}
```

#### 解决兄弟元素 margin 折叠

将其中一个兄弟元素包裹在一个创建了 BFC 的容器中：

```
<div class="bfc-wrapper">
  <div class="box">盒子A</div>
</div>
<div class="box">盒子B</div>
```

```
.bfc-wrapper { overflow: hidden; }  /* 创建 BFC */
.box { margin: 10px 0; }
```

此时两个 `.box` 的 margin 不再折叠，间距为 20px。

### 推荐：`display: flow-root`

`overflow: hidden` 虽然能创建 BFC，但可能导致内容被裁剪或出现滚动条，且语义不清晰。**`display: flow-root`** 是专门为此设计的值，无任何副作用，语义明确——它创建一个新的流式布局上下文，行为类似根元素 `<html>`。

```
.container {
  display: flow-root;  /* 现代浏览器推荐方案 */
}
```

## 面试总结

### 讲一讲盒模型

盒模型包含四层，从外到内分别为margin,border,padding,content内容四个区域。

### 什么是标准盒模型？ 它和IE盒模型有什么区别?

标准盒模型为content-box,width和height只定义内容区的尺寸，padding和border会额外叠加到最终渲染尺寸上。元素的总高度为长/宽 + margin + padding总大小 + border总大小

IE盒模型为border-box,width和height已经包含了内容、内边距和边框，设置多少就是多少，无需额外计算。内容区的实际宽度 = width - padding- border。
通过设置box-sizing属性,可以定义浏览器如何计算元素的总宽度和总高度。

### 什么是BFC? 外边距塌陷是什么？ 改如何解决？

BFC(块级格式化上下文)，是 Web 页面可视化 CSS 渲染的一部分，是一个独立的渲染区域（布局环境）,是块级盒子布局发生的区域，该区域内部的布局与外部完全隔离。 BFC的三大核心作用为 1.包含内部浮动（解决父元素高度坍塌）2. 排除外部浮动（实现自适应两栏布局）3. 阻止外边距折叠（margin collapse）

margin折叠(外边距塌陷),块级元素的上下外边距有时会合并（折叠）为一个外边距，大小取自单个外边距中的最大值。在一对父子元素中，为父级元素设置CSS属性overflow: hidden; display: flow-root;为父级元素创建BFC可以阻止子元素的margin溢出。现代浏览器方案为设置属性display: flow-root。
