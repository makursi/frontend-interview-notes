# CSS 定位与层叠知识点详解

## 一、position 的五个值及区别

`position` 属性用于指定元素在文档中的定位方式，配合 `top`/`right`/`bottom`/`left`（物理属性）或 `inset-*`（逻辑属性）决定最终位置。

### 1. static（静态定位）

- **默认值**，元素按正常文档流布局。
- `top`/`right`/`bottom`/`left`/`z-index` **全部无效**。
- 不脱离文档流，不创建层叠上下文。

### 2. relative（相对定位）

- 元素**仍在正常文档流中**，占据原有空间。
- 基于 `top/right/bottom/left` **相对于自身原始位置**偏移。
- 偏移**不影响其他元素**的位置（其他元素仍按它在原位时布局）。
- 当 `z-index` 不为 `auto` 时，会创建新的层叠上下文。
- **典型用途**：作为绝对定位子元素的"定位祖先"（参照物）。

### 3. absolute（绝对定位）

- **脱离正常文档流**，不为其预留空间，其他元素当它不存在。
- 相对于**最近的定位祖先**（即 `position` 非 `static` 的祖先）定位；若没有，则相对于**初始包含块**（视口/根元素）。
- 最终位置由 `top/right/bottom/left` 决定。
- 当 `z-index` 不为 `auto` 时创建层叠上下文。
- 绝对定位元素的**外边距不会与其他边距折叠**。
- 会为其内容建立新的 BFC。

### 4. fixed（固定定位）

- **脱离正常文档流**，不预留空间。
- 相对于**视口**（viewport）建立的初始包含块定位，滚动时位置不变。
- **总会创建新的层叠上下文**。
- **特殊情况**：若祖先元素设置了 `transform`/`perspective`/`filter` 不为 `none`，则该祖先会取代视口成为包含块（这是常见的"fixed 失效"坑）。
- 打印时，元素在每一页位置相同。

### 5. sticky（粘性定位）

- 元素先按**正常文档流**定位，然后相对于**最近滚动祖先**和包含块偏移。
- 行为是 `relative` + `fixed` 的混合：未到阈值前像 relative，到达阈值后"粘住"像 fixed。
- **总会创建新的层叠上下文**。
- **必须至少设置一个 inset 属性**（如 `top: 0`），否则表现与 relative 无异。
- 会"固定"在最近的拥有滚动机制的祖先上（`overflow` 为 `hidden/scroll/auto/overlay`）。

### 五个值对比速查表

| 特性 | static | relative | absolute | fixed | sticky |
| --- | --- | --- | --- | --- | --- |
| 是否脱离文档流 | 否 | 否 | 是 | 是 | 否 |
| 定位参照物 | 无 | 自身原位 | 最近定位祖先 | 视口 | 最近滚动祖先 |
| top/left 是否生效 | 否 | 是 | 是 | 是 | 是 |
| 是否创建层叠上下文 | 否 | z-index≠auto 时 | z-index≠auto 时 | 总是 | 总是 |
| 是否创建 BFC | 否 | 否 | 是 | 是 | 否 |

## 三、层叠上下文与 z-index 工作原理

### 什么是层叠上下文

层叠上下文（Stacking Context）是 HTML 元素沿**虚构 z 轴**（垂直于屏幕，指向用户）的三维构想。元素基于其属性按优先级顺序占据这个空间，决定了元素重叠时的**渲染先后顺序**。

### 层叠上下文的触发条件

满足以下**任一条件**的元素会创建层叠上下文：

1. **文档根元素**（`<html>`）
2. `position: absolute/relative` **且** `z-index` 不为 `auto`
3. `position: fixed` 或 `sticky`（**无论 z-index 值如何**，总是创建）
4. flex/grid 容器的**子元素**，且 `z-index` 不为 `auto`
5. `opacity < 1` 的元素
6. `mix-blend-mode` 不为 `normal` 的元素
7. 以下属性不为 `none` 的元素：`transform`、`filter`、`backdrop-filter`、`perspective`、`clip-path`、`mask`/`mask-image`/`mask-border`
8. `isolation: isolate` 的元素
9. `will-change` 设置了会创建层叠上下文的属性
10. `contain: layout`/`paint`（或包含它们的合成值如 `strict`/`content`）

### z-index 的工作原理

`z-index` 只对**定位元素**（position 非 static）和 flex/grid 子元素有效，值为整数（可正、可负、可为 0），值越大越靠近用户（越在上层）。

**核心规则——层叠上下文的"自包含"特性：**

> 
> 子级层叠上下文的 `z-index` 值**只在父级中才有意义**。子级层叠上下文被自动视为父级层叠上下文的一个**独立单元**，整体参与父级的层叠排序。

这意味着：

- 层叠上下文可以嵌套，形成层级树。
- 每个层叠上下文**完全独立于兄弟元素**，处理层叠时只考虑自己的子元素。
- 每个层叠上下文是**自包含**的：内部元素层叠完成后，整个元素作为一个整体在父级中排序。

### 经典示例：为什么 z-index: 9999 还是被挡住？

```
Root (层叠上下文)
├── DIV#1  z-index: 5
└── DIV#3  z-index: 4  (创建了层叠上下文)
    ├── DIV#5  z-index: 1
    ├── DIV#6  z-index: 3
    └── DIV#4  z-index: 6  ← 虽然 z-index=6，但它在 DIV#3 内部
```

最终渲染顺序（从下到上）：

```
DIV#2 (z-index:2) → DIV#3 (z-index:4)
  └─ 内部: DIV#5(4.1) → DIV#6(4.3) → DIV#4(4.6)
→ DIV#1 (z-index:5)
```

**DIV#4 的 z-index 是 6，但因为它隶属于 z-index=4 的 DIV#3，整体排在 z-index=5 的 DIV#1 之下。** 这就是"z-index 很大却被挡住"的根本原因——父级层叠上下文的层级决定了整体的上下限。

### 层叠顺序（同一层叠上下文内，从下到上）

1. 形成层叠上下文的元素的**背景和边框**
2. **z-index 为负值**的子元素层叠上下文
3. **块级**非定位子元素（正常流）
4. **浮动**非定位子元素
5. **行内**非定位子元素
6. **z-index: 0 / auto** 的定位子元素
7. **z-index 为正值**的子元素层叠上下文

## 面试总结

position 共有五个常用值：static、relative、absolute、fixed、sticky。 它们之间的对比在于几点,首先absolute，fixed属性会脱离文档流，fixed,stick属性y总会创建层叠上下文。

层叠上下文（Stacking Context）是 HTML 元素沿虚构 z 轴（垂直于屏幕指向用户）的三维构想，决定了元素重叠时的渲染先后顺序。它是一个自包含的层级单元，内部元素的层叠排序独立于外部。 

z-index只对定位元素(position 非 static)和 flex/grid 子元素生效，值为整数，值越大越靠近用户。核心规则为:子级层叠上下文的z-index**只在父级层叠上下文中才有意义。**子级层叠上下文被视为父级中的一个**独立单元**，整体参与父级排序。

父级层叠上下文的层级决定了子元素的整体上下限。即使子元素 `z-index: 9999`，如果它所在的父级层叠上下文整体排在另一个元素之下，子元素也无法超越。例如:父A(z-index:4)和父B(z-index:5), 那子A(z-index:9999)属性值极大，但也突破不了父B的层叠上下文大于父A这一限制
